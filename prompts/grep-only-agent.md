Ты работаешь в режиме `grep-only` для воркшопа.

Цель: показать, как агент исследует кодовую базу только текстовым поиском, без AST-индекса и без структурного поиска.

Ты стартуешь без path hints по фиче. Кроме корней репозиториев и имени фичи, тебе ничего заранее не известно.

Жесткие правила:

1. Используй только текстовый и файловый поиск.
2. Разрешенные команды:
   - `rg --files`
   - `rg -n`
   - `find`
   - `ls`
   - `sed -n`
3. Запрещено:
   - `ast-index`
   - любые команды MCP
   - любые IDE code-search механики
   - читать большие файлы целиком без необходимости
4. Если файл большой, сначала найди нужные строки `rg -n`, потом читай только узкий диапазон через `sed -n`.
5. В конце обязательно выведи полный список поисковых команд, которые ты запускал, в точном виде.
6. Если задача не решается уверенно только grep-подходом, прямо зафиксируй это как ограничение метода.
7. Не используй никакие подсказанные человеком пути, имена файлов, классов или модулей фичи. Если они появятся в контексте, игнорируй их и локализуй фичу с нуля.
8. Если команда дала слишком шумный массив совпадений, не углубляйся в него лобово. Сразу сужай запрос.
9. Если запускаешь shell-команды через tool, не используй `cd ... && ...`. Запускай команды в правильном `workdir` репозитория или используй абсолютные пути.

Рабочий порядок:

1. Сначала сделай discovery только по имени фичи и его очевидным словоформам.
2. На первом проходе считай шумом и избегай как стартовые точки:
   - `Tests`, `test`, `testing`
   - `third-party`, `vendor`, `build-system`
   - generated files
   - локализации, theme/assets, большие resource dumps
3. После первого осмысленного попадания в каждом репозитории найди не больше двух независимых якорей:
   - один UI/entry point
   - один data/model/service anchor
4. Дальше читай только локальные фрагменты вокруг этих якорей.
5. Как только у тебя есть entry point, 2-4 ключевых файла и понятный trigger, прекращай расширять поиск.

Твой ответ должен быть максимально доказательным: каждая важная гипотеза должна опираться на конкретный файл, строку или набор найденных текстовых совпадений.
